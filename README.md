# Crack Severity Pipeline

วัดความกว้างสูงสุดของรอยแตกบนผิวถนนจากภาพถ่าย และจำแนกระดับความรุนแรง โดยใช้ YOLO11 instance segmentation ร่วมกับการวัดเชิงเรขาคณิต (skeletonization + distance transform)

```
ภาพถ่าย → YOLO11-seg → mask รอยแตก → skeleton + distance transform
        → ความกว้างสูงสุด (pixel) → × สเกล → มิลลิเมตร → ระดับความรุนแรง
```

## เริ่มใช้งานเร็ว

```bash
python crack_severity.py \
  --source path/to/image.jpg \
  --model path/to/ACE_1.pt \
  --mm-per-pixel 0.10 \
  --device cpu
```

ผลลัพธ์จะถูกเขียนลง `outputs/` ได้แก่ภาพ overlay, mask, skeleton, JSON รายภาพ และ `summary.csv`

## ติดตั้ง

ต้องใช้ Python 3.10 ขึ้นไป (พัฒนาและทดสอบบน 3.11)

## การคาลิเบรตสเกล

ภาพเปล่าๆ ไม่มีข้อมูลขนาดทางกายภาพ **จึงต้องระบุสเกลเสมอ** โปรแกรมจะไม่เดาค่าให้ และจะ error ถ้าไม่ระบุ เลือกได้ 3 วิธี:

**1. รู้ค่า mm ต่อ pixel โดยตรง**

```bash
python crack_severity.py --source image.jpg --mm-per-pixel 0.10
```

**2. มีวัตถุอ้างอิงในภาพ** — เช่น แท่งอ้างอิงยาวจริง 20 mm วัดในภาพได้ 250 pixels

```bash
python crack_severity.py --source images/ --reference-mm 20 --reference-pixels 250
```

**3. รู้ความกว้างพื้นที่จริงที่ภาพครอบคลุม** — เช่น ภาพทั้งใบครอบคลุมพื้นผิวกว้าง 300 mm

```bash
python crack_severity.py --source image.jpg --image-width-mm 300
```

> วิธีที่ 3 คำนวณจากความกว้างภาพเป็น pixel จึงใช้ได้ก็ต่อเมื่อภาพทุกใบในชุดถ่ายที่ระยะเดียวกันและมีขนาด pixel เท่ากัน

## ตัวเลือกทั้งหมด

| ตัวเลือก | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `--source` | *(บังคับ)* | ไฟล์ภาพ หรือโฟลเดอร์ภาพ |
| `--model` | `../gdrive_download/weights/ACE_1.pt` | ไฟล์โมเดล `.pt` |
| `--output` | `./outputs` | โฟลเดอร์ผลลัพธ์ |
| `--crack-class` | `crack` | ชื่อคลาสที่จะวัด คั่นด้วย comma ได้ หรือ `all` |
| `--conf` | `0.25` | confidence threshold ของ YOLO |
| `--mask-threshold` | `0.75` | เกณฑ์ตัด mask เป็น binary (0–1) ยิ่งสูง mask ยิ่งแคบ |
| `--erosion-kernel` | `3` | ขนาด kernel ของ erosion (ต้องเป็นเลขคี่) |
| `--erosion-iterations` | `1` | จำนวนรอบ erosion ตั้ง `0` เพื่อปิด |
| `--imgsz` | `1280` | ขนาดภาพที่ป้อนเข้าโมเดล |
| `--device` | `cpu` | `cpu`, `mps` หรือหมายเลข CUDA เช่น `0` |

รองรับนามสกุลภาพ: `.jpg .jpeg .png .bmp .tif .tiff .webp`

**หมายเหตุเรื่อง `--imgsz`** — ค่าเริ่มต้นคือ 1280 แต่โมเดลเทรนมาที่ 1024 การรันคนละขนาดกับตอนเทรนทำให้ผลต่างจาก benchmark ได้ ถ้าต้องการผลที่ตรงกับตอน validate ให้ใช้ `--imgsz 1024`

## ผลลัพธ์ที่ได้

ต่อภาพ 1 ใบจะได้ 4 ไฟล์ (`{ชื่อภาพ}_*`) บวก `summary.csv` รวมทั้งชุด

| ไฟล์ | เนื้อหา |
|---|---|
| `*_result.jpg` | ภาพต้นฉบับ + mask สีแดง + skeleton สีเหลือง + วงกลมชมพูที่จุดกว้างสุด + ป้ายค่า |
| `*_mask.png` | binary mask ของรอยแตก (0/255) |
| `*_skeleton.png` | เส้นแกนกลางที่ได้จาก skeletonization |
| `*_result.json` | ค่าที่วัดได้ทั้งหมด |
| `summary.csv` | รวมทุกภาพเป็นตารางเดียว (encoding `utf-8-sig` เปิดใน Excel ได้เลย) |

โครงสร้าง JSON / คอลัมน์ CSV:

| ฟิลด์ | ชนิด | ความหมาย |
|---|---|---|
| `image` | str | path ของภาพต้นทาง |
| `max_width_px` | float | ความกว้างสูงสุดหน่วย pixel |
| `max_width_mm` | float | ความกว้างสูงสุดหน่วยมิลลิเมตร |
| `severity` | str | `เล็กน้อย` / `ปานกลาง` / `สูง` |
| `mm_per_pixel` | float | สเกลที่ใช้คำนวณ |
| `crack_area_px` | int | จำนวน pixel ทั้งหมดใน mask |
| `max_point_x`, `max_point_y` | int \| null | พิกัดจุดที่กว้างที่สุด (`null` ถ้าไม่พบรอยแตก) |
| `detections_used` | int | จำนวน instance ที่ถูกรวมเข้า mask |

**เกณฑ์ความรุนแรง**

| ความกว้างสูงสุด | ระดับ |
|---|---|
| ≤ 3 mm | เล็กน้อย |
| > 3 – 6 mm | ปานกลาง |
| > 6 mm | สูง |

> ⚠️ เกณฑ์ชุดนี้ฝังอยู่ใน `severity_from_mm()` ([crack_severity.py:33](crack_severity.py#L33)) และ **ยังไม่ได้ระบุแหล่งอ้างอิงมาตรฐาน** ผู้รับช่วงต่อควรยืนยันกับมาตรฐานที่หน่วยงานใช้จริง (เช่น ASTM D6433 หรือคู่มือของกรมทางหลวง) ก่อนนำผลไปใช้ตัดสินใจ

## อัลกอริทึม

1. **Segmentation** — รัน YOLO11-seg ด้วย `retina_masks=True` เพื่อให้ mask มีความละเอียดเท่าภาพต้นฉบับ แทนที่จะเป็น 1/4 ตามค่าเริ่มต้น
2. **รวม mask** — เอา mask ของทุก instance ที่อยู่ในคลาสที่เลือก มา OR รวมเป็นก้อนเดียว โดยตัดที่ `--mask-threshold`
3. **Erosion** — กัดขอบ mask เข้า 1 รอบด้วย kernel วงรี 3×3 เพื่อชดเชยขอบที่บวมจาก segmentation
4. **Skeletonization** — หาเส้นแกนกลางด้วย morphological thinning (erode → dilate → เก็บส่วนต่าง วนจนหมด)
5. **Distance transform** — คำนวณระยะ Euclidean จากทุก pixel ถึงขอบ mask ที่ใกล้ที่สุด
6. **ความกว้างสูงสุด** = `2 × max(distance ที่ตำแหน่ง skeleton)` — คือเส้นผ่านศูนย์กลางของวงกลมใหญ่สุดที่บรรจุใน mask ได้
7. **แปลงหน่วย** — `mm = pixel × mm_per_pixel` แล้วจำแนกระดับ

จุดสำคัญคือขั้นที่ 6: การวัดที่ตำแหน่ง skeleton ทำให้ได้ความกว้าง **ตั้งฉากกับแนวรอยแตก** โดยอัตโนมัติ ไม่ว่ารอยแตกจะเอียงหรือโค้งอย่างไร ซึ่งแม่นกว่าการวัดตามแนวแกน x หรือ y ตรงๆ

## การตรวจสอบความแม่นยำ

`validate_measurement.py` สร้าง mask สังเคราะห์ที่รู้ความกว้างจริง แล้วป้อนเข้า `measure_mask()` ตัวเดียวกับที่ pipeline ใช้ เพื่อวัด error โดยไม่ต้องพึ่งโมเดล

```bash
python validate_measurement.py                    # รันเทสต์
python validate_measurement.py --save-debug dbg/  # บันทึกภาพ mask/skeleton ไว้ตรวจด้วยตา
```

exit code `0` = ผ่านทั้งหมด, `1` = มีเคสไม่ผ่าน

ผลล่าสุด (ผ่านทั้ง 12 เคส):

| เคส | ค่าจริง (px) | วัดได้ (px) | error |
|---|---|---|---|
| เส้นตรงแนวนอน 3 px | 3.00 | 4.00 | +33.3% |
| เส้นตรงแนวนอน 5 px | 5.00 | 6.00 | +20.0% |
| เส้นตรงแนวนอน 9 px | 9.00 | 10.00 | +11.1% |
| เส้นตรงแนวนอน 15 px | 15.00 | 16.00 | +6.7% |
| เส้นตรงแนวนอน 21 px | 21.00 | 22.00 | +4.8% |
| เส้นตรงแนวนอน 31 px | 31.00 | 32.00 | +3.2% |
| เส้นตรงแนวตั้ง 15 px | 15.00 | 16.00 | +6.7% |
| เส้นเฉียง 45° 15 px | 15.00 | 16.97 | +13.1% |
| เส้นเฉียง 30° 9 px | 9.00 | 8.94 | −0.6% |
| วงแหวน รัศมี 80 px กว้าง 11 px | 11.00 | 12.00 | +9.1% |
| ส่วนโค้ง (arc) 13 px | 13.00 | 16.00 | +23.1% |
| เส้นกว้างไม่เท่ากัน 5→25 px | 25.00 | 24.00 | −4.0% |

**สิ่งที่ผลนี้บอก**

- มี **bias คงที่ประมาณ +1 pixel** ในเคสเส้นตรงทุกขนาด มาจากการที่ distance transform นับ pixel ศูนย์กลางเข้าไปด้วย เมื่อคูณ 2 จึงเกินจริง ~1 px
- bias คงที่นี้แปลว่า **error เป็นเปอร์เซ็นต์จะสูงมากกับรอยแตกเส้นเล็ก** — ที่ 3 px ผิด 33% แต่ที่ 31 px ผิดแค่ 3% รอยแตกยิ่งบาง ผลยิ่งเชื่อถือได้น้อย
- เคสส่วนโค้งผิด +23% สูงกว่าเคสอื่น เพราะ skeleton ของส่วนโค้งมีปลายแตกแขนง (spur) ทำให้จับจุดกว้างเกินจริง
- ค่า tolerance ในเทสต์ตั้งไว้กว้าง (1.5–3.0 px) จึง "ผ่าน" ทั้งที่ยังมี bias อยู่ — **ถือว่าเป็น regression test ไม่ใช่การรับรองความแม่นยำ**

หากต้องการความแม่นยำสูงขึ้น ทางที่ตรงที่สุดคือหักค่าชดเชย ~1 px ออกจาก `max_width_px` แต่ควรตรวจกับรอยแตกจริงที่วัดด้วยเกจก่อน

## ข้อจำกัดที่ต้องรู้ก่อนใช้งานจริง

**1. คุณภาพ mask คือคอขวดหลัก**

pipeline วัดจาก mask ที่โมเดลทำนายมา ถ้า mask ผิด ค่าที่วัดก็ผิดตาม จากการ validate โมเดล `ACE_1.pt` บนชุด `merged_dataset_v2_1280`:

| | crack (val) | crack (test) |
|---|---|---|
| Box mAP50-95 | 0.461 | 0.377 |
| **Seg mAP50-95** | **0.175** | **0.139** |

mask ของคลาส `crack` มีคุณภาพต่ำที่สุดในสามคลาส เพราะรอยแตกเป็นวัตถุเรียวบาง ขอบ mask คลาดเคลื่อนไม่กี่ pixel ก็กระทบความกว้างเป็นเปอร์เซ็นต์สูง **ตัวเลข mm ที่ได้จึงควรถือเป็นค่าประมาณเพื่อคัดกรอง ไม่ใช่ค่าวัดเชิงวิศวกรรม**

**2. Recall ต่ำ — รอยแตกที่หาไม่เจอจะไม่ถูกรายงานเลย**

โมเดลมี recall ~0.50 คือมองข้ามรอยแตกไปประมาณครึ่งหนึ่ง ภาพที่ pipeline รายงานว่า "ไม่พบรอยแตก" ไม่ได้แปลว่าไม่มี

**3. วัดในระนาบภาพเท่านั้น**

ค่าที่ได้คือความกว้างบนภาพ 2 มิติ ไม่ใช่ระยะจริงเชิง 3 มิติ ภาพต้องถ่าย**ตั้งฉาก**กับพื้นผิว และวัตถุคาลิเบรตต้องอยู่ระนาบเดียวกับรอยแตก ถ้าถ่ายเอียงจะเกิด perspective distortion ที่ pipeline ไม่ได้แก้ให้

**4. Erosion ทำให้ค่าแคบลง**

ค่าเริ่มต้น `--erosion-iterations 1` หัก mask ออกประมาณ 1 pixel รอบด้าน ซึ่งบังเอิญไปหักล้างกับ bias +1 px ในข้อ 1 ของหัวข้อ validate พอดี **การเปลี่ยนค่านี้จะทำให้ผลเลื่อนอย่างมีนัยสำคัญ** ถ้าเปลี่ยนต้องคาลิเบรตใหม่ทั้งชุด

**5. รวมทุกรอยเป็นก้อนเดียว**

`build_crack_mask()` ใช้ OR รวม mask ทุก instance ภาพที่มีรอยแตกหลายเส้นจะได้ค่าเดียวคือความกว้างของเส้นที่กว้างที่สุด ไม่มีการแยกรายเส้น ถ้าต้องการรายงานทีละรอย ต้องแก้ให้วนทีละ instance

**6. `--imgsz` เริ่มต้นไม่ตรงกับที่โมเดลเทรนมา**

ดูหัวข้อ [ตัวเลือกทั้งหมด](#ตัวเลือกทั้งหมด)

**7. เกณฑ์ severity ยังไม่มีแหล่งอ้างอิง**

ดูหัวข้อ [ผลลัพธ์ที่ได้](#ผลลัพธ์ที่ได้)
